# フロントエンドの暫定方針

::: warning 仮採用・デザインは未確定
**プレーンな明色・アースカラーの方向性（案1）**を当面の作業基準とします。デザインテイスト、ブランドの表現、細かな操作コンセプトは完全には固まっていません。フロントは頻繁に変わる前提とし、深いデザイン作業は将来別途行います。固定されたデザインシステムや、製品としての提供準備完了を意味しません。
:::

## この引き継ぎで用意するもの

[操作できるHTML見本を開く](../design/plain/index.html?lang=ja)。Google Cloud、API、ビルド、認証情報、外部アセットは不要です。ファイルは `apps/guide-internal/public/design/plain/` にあり、`index.html` を直接開いても動きます。日本語・英語と架空の結果状態を切り替えられます。識別子と金額はすべて架空です。

これは**デザイン資料であり、アプリ本体のフロントではありません**。案1の方向性を初回Google Cloud診断へ適用したもので、以前の全機能モックをピクセル単位で保存したものではありません。この見本に業務ロジックを追加し続けないでください。アプリ内プレビューで同じ体験を確認できるようになったら、HTML見本を廃止するか、過去の参考資料であることを明記します。

暗色・宝箱の方向性（案2）は保留であり、永久に棄却するものではありません。今は2テーマを実装しません。どちらの過去モックも、メニューに存在することを機能の採用決定と解釈しません。

## 維持する制約と、変えてよいもの

| 見た目の変更中も維持するもの | 暫定・差し替えてよいもの |
| --- | --- |
| 候補と判定根拠、不確実性、取得範囲 | 色、書体、余白、配置、文言、猫の置き方 |
| 概算・金額不明・実現済み削減額の区別 | 表、展開式、ドロワー、詳細ページなどの表示方式 |
| 明示的な診断実行、リソースの自動変更をしないこと | ナビゲーション構成、将来の明色・暗色対応 |
| 現在の結果仕様と、UI・取得・評価の責務分離 | アプリの成長に合わせたコンポーネント境界 |

[コンセプト](./concept)にある製品の存在意義は維持します。今回の暫定判断はフロントとその表現に関するもので、安全性の要件や対象ユーザーを白紙に戻すものではありません。

## 見た目の作業基準

- 薄い背景 `#f7f9f6`、白い作業面、静かなサイドバー `#f2f5ef`、本文 `#293630`、深緑の主色 `#285642`、罫線 `#e0e6dd`。見本CSSでは意味ごとに差し替え可能な変数へまとめます。
- システムフォント、本文16px、通常ラベル14px、桁を揃えた数値。フォーカス表示とキーボード操作を維持し、狭い画面や文字拡大にも対応します。
- 大きなカードの反復、強い影、グラデーション、大きなイラストより、簡潔な概要・行・区切り・段階的な根拠の表示を優先します。
- 小さな休む猫は脇役です。猫がなくても結果を理解できるようにし、エラーや取得不完全を祝祭的に表現しません。緑色は環境貢献を約束する意味ではありません。
- 装飾的な文言より役立つ事実を先に示します。「見直し候補」とし、「安全に削除できる」「利益を獲得した」と断定しません。

## 見本の範囲

**実行結果の概要 → 候補一覧 → 判定根拠**を扱います。候補あり、候補多数、該当なし、部分取得、金額不明、認証失敗、通信失敗、読み込み中を切り替えます。詳細では識別子・場所・取得時点の状態・参照先・ルールと版・概算の前提・未使用期間不明・人による確認事項を示します。選択済みプロジェクトを表示しますが、導入や連携設定は実装しません。

実接続、保存、履歴、検索、フィルター、定期診断、Slack連携、グラフ、年間削減の約束、リソース変更は追加しません。まだ実診断の結果コンポーネントは使わず、独立したHTML・CSS・JavaScriptの資料として隔離します。

## アプリ内プレビュー — v0.1予定・顧客向け未提供

1. プレビューを改善する間も、現在のローカル診断の動作を維持します。
2. 既存の技術構成で `apps/web` に開発専用プレビューを提供します。新たなUIフレームワークやコンポーネント開発ツールの必須導入は不要です。
3. `apps/web/src/diagnostics/results.tsx` の `DiagnosticResults` を実データ・架空データで共用します。必要な表示部品だけを分け、デバッグパネルのCSSラッパーへの依存は必要に応じて外します。
4. 結果仕様は `packages/core/src/diagnostics.ts` の `DiagnosticResult` を維持します。架空の結果も実応答と同じ境界検証を通します。読み込み中・通信失敗はリクエストの状態であり、成功結果を捏造しません。認証失敗は現在の結果仕様でも表現できます。
5. 取得、認証情報、診断、価格算出を表示コンポーネントに持ち込みません。色などの変数はWebアプリ側のスタイルへ適用し、この独立HTMLの描画処理や以前のモックのフレームワーク依存を移植しません。
6. 将来の保存済み結果も同じ表示へ渡せるようにします。ローカルD1保存、履歴の改善、診断のWorkflow化は別の変更であり、UIプレビューの前提にしません。

現在の価格は固定単価による **USD/月**で、確認済みの請求額や実現済み削減額ではありません。金額不明の候補は残し、算出分の小計から除外します。年間換算や通貨換算には前提が必要です。以前の架空の円金額や「30日間未使用」を持ち込まないでください。[診断設計](./diagnostics)と[ローカル検証](./local-debug)も参照してください。

## 開発専用プレビューの使い方

リポジトリのルートで`pnpm --filter @luckycat/web dev`を実行し、Webサーバーの`/dev/diagnostics`を開きます。通常の`pnpm dev`でも、他のアプリと一緒に起動します。APIサーバーとGoogle Cloud認証情報は不要です。8状態と日英を切り替え、候補の行を開いて根拠を確認します。実診断と同じ`DiagnosticResults`を使い、モックであることとデザイン・価格の仮実装を明示します。読み込み中と通信失敗はリクエスト状態として表示します。本番ビルドではプレビューにアクセスできず、架空データも含めません。

HTML見本は引き継ぎ時の参考資料として保持します。アプリ側に業務ロジックを集約し、独立HTMLの廃止または過去資料への正式な位置づけ変更は別途判断します。

## 受け入れチェック

- クラウド接続なしで見本を開け、操作は架空の表示状態だけを変更する。
- すべての状態で、デザインが暫定であることとモック表記が見える。
- 候補ありと部分取得が両立し、情報不足を該当なしにしない。
- 該当なしは評価済みの範囲に限り、環境全体の安全宣言にしない。
- 金額不明は0円ではなく、小計には算出対象を明示する。
- 50候補を行として扱え、詳細の長い識別子が折り返される。
- アプリ内プレビューでは、実データと架空データが同じ描画処理を使い、既存の安全性テストを維持する。

この資料とアセットは、将来承認されたマージ後に既存の**公開**内部ガイドへ配置される対象です。架空・自己完結の内容に限定します。今回の引き継ぎは、コミット・push・デプロイや、非公開の会話・認証情報・顧客の診断結果・非公開参考URLを含める許可ではありません。
