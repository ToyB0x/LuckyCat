# 初回診断の設計

::: info v0.1予定・未提供
Google Cloudの連携設定 → 接続と権限の確認 → 対象を限定した取得 → ルール評価 → 改善候補と根拠の確認が確定した体験です。顧客向け機能は未提供です。開発用には以下の最初の2ルールを実装し、停止VMのルールは停止期間と除外条件の決定後に追加します。
:::

## 小さな初回ルール群

Compute Engineのリソース情報を共有できる3候補を優先します。検知は請求エクスポートやBigQueryなしで成立させ、金額は独立した追加情報とします。ルール1種類に制限せず、網羅的な提供も約束しません。

| 候補・推奨 | 必要データ・API権限の候補 | 観測と判定条件 | 除外・根拠不足 |
| --- | --- | --- | --- |
| 未接続の永続ディスク — 採用推奨 | 状態、識別情報、場所、種別、容量、接続先。`disks.aggregatedList`、`compute.disks.list`。 | 現在の一覧で接続先がないことを確認する。連続した未使用期間を条件にするなら履歴が必要。作成からの経過時間はリソースの年齢にすぎない。 | 接続済みや準備完了前の状態は除外する。接続・状態が不明なら、APIのフィールド仕様に照らして未評価とする。復旧・移行用の保持は人が確認する。 |
| 未割り当ての静的外部IPv4 — 採用推奨 | アドレスの範囲、種別、IPバージョン、予約状態、参照先。`addresses.aggregatedList`、`compute.addresses.list`。 | 現在予約中の外部IPv4に参照先がない。猶予期間や連続した未使用の表現には、時間の根拠を定める。 | 内部アドレス、IPv6、使用中は除外する。状態・参照情報の欠損や矛盾は未評価。再利用予定は一覧だけでは分からない。 |
| 停止VMに残るディスク — 停止期間の決定を条件に採用推奨 | ディスク一覧に加え、VMの識別情報、状態、停止時刻、接続関係。`instances.aggregatedList`、`compute.instances.list`とディスクの読み取り。 | 全接続先が評価対象の停止VMに対応し、合意した停止期間を満たす。実際の遷移時刻を使い、ディスク作成時刻で代用しない。 | 稼働中の接続先があれば除外。不明・対象外・未解決の接続先や、停止時刻の欠損・不正は完全な評価を妨げる。サスペンド状態や保持例外は明示的に方針を決める。 |

公式資料の[ディスク](https://docs.cloud.google.com/compute/docs/reference/rest/v1/disks/aggregatedList)、[アドレス](https://docs.cloud.google.com/compute/docs/reference/rest/v1/addresses/aggregatedList)、[VM一覧](https://docs.cloud.google.com/compute/docs/reference/rest/v1/instances/aggregatedList)に基づく権限候補であり、導入用の完全な権限設定ではありません。リージョン・ゾーン・グローバルの取得範囲、ページング、部分成功の警告、追加APIの必要性を確認してからロールを選びます。読み取りスコープはIAMの認可の代わりにはなりません。

### その他の候補

| 候補 | データ・観測・権限 | 判断と理由 |
| --- | --- | --- |
| スナップショットの保持見直し | 識別情報、作成時刻、保存情報、保持目的。Computeの[`snapshots.list`](https://docs.cloud.google.com/compute/docs/reference/rest/v1/snapshots/list) / `compute.snapshots.list`。経過時間は分かるが、復旧価値がないことは分からない。 | 要確認。バックアップ、復旧、法令対応の保持方針と例外を定めるまで後回しを推奨。古いという理由だけでは不十分。 |
| VMの低利用・サイズ最適化 | Computeの一覧とMonitoringの時系列（[`monitoring.timeSeries.list`](https://docs.cloud.google.com/monitoring/access-control)）、指標定義、集計方法、十分な観測期間。CPUだけでは処理特性やメモリの余裕を判断できない。 | 後回し。追加データ・権限と、処理特性を踏まえた閾値が必要。欠測、周期的な処理、メモリの未観測を未使用と扱わない。 |

### 金額と採用までの不足

| 候補 | 金額に必要な追加の根拠 | 採用前に必要なこと |
| --- | --- | --- |
| 未接続ディスク | 種別・場所・容量に対応する確認済みの価格と時間の基準、または正しく対応付けた請求データ。 | 猶予期間の意味と保持例外を決め、接続関係の完全な取得と不明状態の扱いを検証する。 |
| 未割り当てIPv4 | リージョン・グローバル、割り当て種別に適した価格と、根拠のある期間。 | 対応するアドレス範囲と状態の整合性を確認する。現在の予約状態と作成時刻から過去の課金を推測で確定しない。 |
| 停止VMのディスク | ディスク価格または請求の根拠。VMの停止時刻だけでは残るストレージの金額を算出できない。 | 停止期間と対象状態を決め、プロジェクト・ゾーンを含む完全なリソース識別子で接続先を対応付ける。共有ディスクの重複計上や部分合計の誤表示を防ぐ。 |
| スナップショット保持 | 保存量の基準、場所、価格または請求の対応。古さだけでは削減額は分からない。 | 保持目的・期間を先に決め、採用前に復旧要件と金額の根拠を検証する。 |
| 低利用・サイズ最適化 | 適切な変更先構成、価格差、割引、利用状況の観測範囲。 | 観測期間、充足条件、ピークの扱い、処理特性による除外を決め、変更先の適合性を確認してから差額を推定する。 |

ローカル診断では、取得・正規化を`apps/api`、純粋なルール評価と結果の型を`packages/core`、認証情報の取得を`packages/oidc`に分けます。採用する各ルールで、該当、根拠のある非該当、フィールド欠損、権限・APIエラー、部分取得、価格不明を検証します。追加の例として、接続先の変化、内部アドレス・IPv6の除外、稼働・停止VMの混在、不正な停止時刻、保持例外、監視履歴の欠測を扱います。テストコードだけで提供可能性を判断せず、LuckyCatの実装と実行環境で検証してから提供します。

## ローカル診断の範囲

- 明示した1プロジェクトのディスク・アドレスをComputeの集約一覧から読み取ります。評価対象はゾーン／リージョンの`pd-standard`・`pd-balanced`・`pd-ssd`・`pd-extreme`と、集約一覧に含まれるリージョン／グローバルの静的外部IPv4です。別APIによる範囲の探索はしません。返されたスコープと未取得の範囲を確認し、組織全体の網羅性を保証しません。
- ディスクは`READY`で参照先なし、IPv4は`EXTERNAL`・`IPV4`・`RESERVED`で参照先なしを候補とします。レプリケーション中のディスク、未対応のディスク種別は未評価です。猶予期間・保持例外の自動判定はまだ行いません。
- 必要なフィールドを明示して取得します。Googleの一覧応答で省略される繰り返しフィールド`users`は参照先0件として正規化し、省略されたことも根拠に残します。`null`・不正な参照先、状態・種別・識別情報の欠損や矛盾は未評価です。`addressType`の省略は公式既定値の`EXTERNAL`として扱い、`ipVersion`が省略されても実際のアドレスが厳密なIPv4形式なら`IPV4`として正規化します。いずれも補完したことを根拠に残し、IPアドレス自体は結果へ含めません。その他の欠損や`null`は未評価です。汎用のcore側では欠損を空配列に変換しません。
- 開発用の上限は取得元ごとに100件×5ページ、最大500件、1応答2MiB、1要求10秒、取得全体30秒です。自動再試行はしません。上限到達、警告、ページ失敗は不完全として残します。同一リソースの矛盾した観測は評価しません。これは本番の上限決定ではありません。
- JSONにはルールID・版、対象、取得開始／終了時刻、取得スコープ、候補と根拠、未評価の理由を含めます。観測は現在の状態のみで連続した未使用期間は不明です。金額は下記の固定単価による仮の推定値、または`unknown`です。部分取得では完全な「該当なし」を返しません。
- 診断はローカルAPIから直接実行し、DBやWorkflowへ結果を保存しません。ローカル画面にリソース識別子を表示するため、JSONを公開ファイルへ貼り付けないでください。既存のWorkflowは接続確認専用です。

## 仮の価格推定

価格推定は現在仮実装です。画面と利用感の確認が目的で、`packages/core/src/prototype-pricing.ts`に固定単価をまとめます。通常の数値演算で月額をセント単位に丸め、価格API、価格の有効期限管理、請求データ接続は追加しません。

- ゾーンのディスクは`pd-standard: $0.04`、`pd-balanced: $0.10`、`pd-ssd: $0.17`／GiB月を容量に掛けます。リージョンのディスクは暫定的に2倍とします。容量不明・不正や`pd-extreme`は金額不明のままです。
- 未割り当ての静的外部IPv4はリージョン／グローバルとも暫定的に`$0.01 × 730時間 = $7.30/月`とします。地域差、割引、無料枠、BYOIPなどの個別条件は未反映です。
- APIと画面は結果形式v2を使い、金額に仮実装の識別子、USD月額、単価、数量、単位を含めます。候補の判定は変えず、価格が分からない候補も残します。小計は算出できた候補だけを対象にし、件数と金額不明の件数を併記します。
- 画面に「価格推定は仮実装」と表示します。現在の状態が続いた場合の概算費用であり、削除・解放でき、代替費用がなければ削減目安となります。実請求額、過去の支出、実現済み削減額とは扱いません。

単価は[ディスク料金](https://cloud.google.com/compute/disks-image-pricing)と[IPv4料金](https://cloud.google.com/vpc/network-pricing#ipaddress)を参考にしたUI用の概算です。正式採用時に、地域・SKU・追加課金・BYOIP・割引等の扱いを検証し、BigQueryのBilling Export、価格REST API、その他の情報を組み合わせて改善します。

## 結果の仕様と受け入れ条件

`packages/core`の`DiagnosticResult`をAPIと画面の共通の結果型とします。画面では候補の有無と評価の完全性を別々に表示し、部分評価・未評価・認証失敗を「該当なし」と混同しません。画面のテストには模擬応答を使い、実クラウドへの接続を必要としません。

認証、取得元ごとのデータ取得、ルール評価、検知、金額を別の状態で扱います。各診断で、指定した範囲、実際に取得・評価できた範囲、取得時点、観測期間、ルールの条件・版、未評価の理由を記録します。

| 状況 | 期待する結果 |
| --- | --- |
| 認証できても必要な取得元が権限拒否・API無効・失敗 | 認証の成功と、その取得元・依存ルールの未評価を両立させる。失敗を問題なし・0件・支出ゼロに変換しない。 |
| 取得元やページの一部が失敗、または取得上限に到達 | 独立して十分な根拠が揃った検知は維持する。依存するルール・リソースは未評価とし、不完全な範囲を示す。部分一覧から存在しないと判断しない。 |
| 完全な一覧が空、または評価できたルールに該当なし | 確認済みの範囲に限って対象なし・該当なしを示し、環境全体の健全性を保証しない。 |
| 検知は成立したが価格・請求が不明 | 検知と根拠を金額不明のまま示す。不明を0にせず、部分金額を全体の合計にしない。 |
| 金額の推定がある | リソースの費用、特定の変更による削減可能額、実現済み削減額を区別する。通貨、期間、前提、共有リソースの扱いを示す。 |
| 未使用・低利用に見える情報がある | 安全に削除できる証明ではなく見直し候補として示す。v0.1で自動削除・リソース変更は行わない。 |

請求データやBigQueryは、それを必要とするルール・金額算出だけの要件とします。金額データの失敗で、成立したリソース情報ベースの検知を隠しません。[接続とデータ管理の提供前条件](./google-cloud#提供前の条件)も満たしてから受け入れます。
